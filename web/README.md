# Веб-интерфейс Calls / SMS

Этот каталог — обновление существующего PHP-хостинга Calls / SMS, а не отдельная установка сайта. Он добавляет «Настройки → Распознавание речи» с выбором **GigaAM** или **faster-whisper**.

Загрузите рядом с существующим `common.php` файлы:

* `index.php`
* `sw.js`
* `transcription_settings.php`
* `transcription_settings_store.php`
* `event_store.php`
* `save_call.php`
* `save_sms.php`
* `offline.html`
* `notifications.js`

Перед заменой сохраните копии заменяемых файлов в закрытом каталоге. Сначала загрузите `event_store.php`, `offline.html` и `notifications.js`, затем `save_call.php` и `save_sms.php`, последними — `index.php` и `sw.js`. Оба endpoint сохранения должны обновляться вместе с UI: они используют общую с удалением блокировку, чтобы параллельные запросы не теряли новые записи. Существующие `common.php`, `vendor/`, `icons/` и `sip-private-data/` остаются на хостинге. `common.php` содержит конфигурацию доступа и намеренно не включён в репозиторий.

Настройка хранится в `DATA_STORAGE_DIR/transcription-settings.json`, запись выполняется атомарно. PHP-пользователь должен иметь право записи в этот каталог. UI требует существующую сессию администратора и CSRF-токен; допустимы только `gigaam` и `whisper`. Бот читает отдельный GET endpoint через тот же заголовок `Authentication`, который используется для сохранения звонков. Запись через этот endpoint запрещена. API, записи разговоров и динамические страницы не кэшируются service worker.

Одновременно обновите бот и его зависимости по инструкции в [../docs/transcription.md](../docs/transcription.md). Один лишь новый UI не меняет поведение старой версии бота. Новый бот по умолчанию находит endpoint рядом с `EVENT_STORE_CALL_URL`; при другом размещении задайте `CALL_TRANSCRIBE_SETTINGS_URL` явно.

Выбор применяется перед началом следующей транскрибации. Уже обрабатываемая запись завершается прежним движком; старые расшифровки не переписываются. Во время недоступности endpoint процесс использует последний успешно прочитанный выбор, а до первого успешного чтения — `CALL_TRANSCRIBE_BACKEND` из окружения.


## Сеть и уведомления

При недоступной сети или сервере service worker показывает сохранённую страницу со спиннером. Она проверяет соединение каждые 5 секунд и автоматически открывает исходную страницу, сохраняя ссылку на событие. В работающем UI потеря сети также включает экран ожидания. POST-запросы после восстановления связи автоматически не повторяются.

Для офлайн-открытия нужен хотя бы один успешный визит после обновления: браузер должен установить service worker и сохранить `offline.html`. На самом первом посещении без интернета браузер ещё не имеет файлов сайта. Требуются HTTPS (либо localhost для теста) и поддержка service worker.

Кнопки уведомлений нет. При каждом открытии страницы UI запрашивает разрешение, если браузер ещё не сохранил решение. Если нужен жест пользователя, запрос повторяется при первом нажатии или клавише. При уже выданном разрешении восстанавливается push-подписка. После явного запрета браузер не позволяет программно запросить разрешение повторно: его можно изменить в настройках сайта. См. [Notification.requestPermission](https://developer.mozilla.org/en-US/docs/Web/API/Notification/requestPermission_static).

## Удаление истории

В списках звонков и СМС можно выбирать отдельные записи или всю текущую страницу. Кнопка показывает количество выбранных записей; перед удалением появляется подтверждение. Выбор ограничен видимыми записями, поиск и пагинация учитываются. После удаления последней страницы UI переходит на оставшуюся страницу.

`POST index.php?action=delete_events` принимает `kind` (`calls` или `sms`), `ids` (1–100 строк) и сессионный `csrf_token`. Нужны ключ доступа и авторизация администратора. Повторный запрос с уже удалёнными ID безопасен. Вместе со звонком удаляется его аудиофайл, если на него больше не ссылаются другие звонки. Ошибка удаления файла отображается в UI; осиротевшая запись недоступна через скачивание. Удаление необратимо.

JSON-хранилище обновляется атомарно под общей блокировкой `<store>.lock`. Повреждённый JSON не перезаписывается. Локальные файлы с историей и ключами не входят в репозиторий.

Проверки без production-конфигурации:

```sh
node --test tests/web_ui.test.cjs
php tests/web_event_store_test.php
```

PHP-тест проверяет удаление и сохранность аудио, валидацию, повреждённое хранилище и одновременное добавление/удаление тремя процессами. JS-тесты проверяют автоматическое разрешение/подписку, обработку запрета, офлайн-ответы service worker и отправку выбранных ID после подтверждения.
