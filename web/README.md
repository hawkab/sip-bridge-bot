# Веб-интерфейс Calls / SMS

Этот каталог — обновление существующего PHP-хостинга Calls / SMS, а не отдельная установка сайта. Он добавляет «Настройки → Распознавание речи» с выбором **GigaAM** или **faster-whisper**.

Загрузите рядом с существующим `common.php` файлы:

* `index.php`
* `sw.js`
* `transcription_settings.php`
* `transcription_settings_store.php`
* `event_store.php`
* `save_call.php`
* `save_sms.php`
* `offline.html`
* `notifications.js`
* `sms_outbox.php`
* `sms_outbox_store.php`
* `voice_outbox.php`
* `voice_outbox_store.php`
* `voice_calls.js`
* `app_session.php`

Перед заменой сохраните копии заменяемых файлов в закрытом каталоге. Сначала загрузите `event_store.php`, `offline.html` и `notifications.js`, затем `save_call.php` и `save_sms.php`, последними — `index.php` и `sw.js`. Оба endpoint сохранения должны обновляться вместе с UI: они используют общую с удалением блокировку, чтобы параллельные запросы не теряли новые записи. Существующие `common.php`, `vendor/`, `icons/` и `sip-private-data/` остаются на хостинге. `common.php` содержит конфигурацию доступа и намеренно не включён в репозиторий.

Настройка хранится в `DATA_STORAGE_DIR/transcription-settings.json`, запись выполняется атомарно. PHP-пользователь должен иметь право записи в этот каталог. UI требует существующую сессию администратора и CSRF-токен; допустимы только `gigaam` и `whisper`. Бот читает отдельный GET endpoint через тот же заголовок `Authentication`, который используется для сохранения звонков. Запись через этот endpoint запрещена. API, записи разговоров и динамические страницы не кэшируются service worker.

Одновременно обновите бот и его зависимости по инструкции в [../docs/transcription.md](../docs/transcription.md). Один лишь новый UI не меняет поведение старой версии бота. Новый бот по умолчанию находит endpoint рядом с `EVENT_STORE_CALL_URL`; при другом размещении задайте `CALL_TRANSCRIBE_SETTINGS_URL` явно.

Выбор применяется перед началом следующей транскрибации. Уже обрабатываемая запись завершается прежним движком; старые расшифровки не переписываются. Во время недоступности endpoint процесс использует последний успешно прочитанный выбор, а до первого успешного чтения — `CALL_TRANSCRIBE_BACKEND` из окружения.


## Сессия на 30 дней

После успешного входа сессия действует 30 дней, включая закрытие и повторный запуск браузера. Срок фиксируется при входе: фоновый опрос не продлевает его бесконечно. «Выйти» немедленно завершает сессию. Cookie сохраняет `HttpOnly`, `SameSite=Lax` и `Secure` при HTTPS; при входе меняется идентификатор сессии.

Для установки один раз обновите функцию `start_app_session()` в приватном `common.php`. Скачайте актуальный файл в закрытый локальный каталог и создайте отдельную копию для загрузки:

```sh
python tools/patch_web_session.py /private/original/common.php /private/deploy/common.php
```

Скрипт меняет только функцию запуска сессии, не выводит секреты и не изменяет исходный файл. **Не добавляйте `common.php` в Git и не размещайте его резервную копию в публичном каталоге сайта.** Сначала загрузите `app_session.php`, затем подготовленный `common.php`, последним — `index.php`. На первой установке потребуется повторный вход: старое общее хранилище сессий не используется.

Серверные данные находятся в `DATA_STORAGE_DIR/sessions` (каталог `0700`, файлы `0600`), внутри уже закрытого для HTTP каталога. `session.gc_maxlifetime` и время жизни cookie равны 2592000 секундам. Отдельное хранилище защищает от преждевременной очистки другими PHP-приложениями с меньшим сроком; см. [документацию PHP](https://www.php.net/manual/en/session.configuration.php#ini.session.gc-maxlifetime). Сервер также проверяет сохранённый срок при каждом запросе, поэтому просроченный cookie не даёт доступ даже до запуска очистки.

Проверка без ключей сайта: `php tests/web_session_test.php`. Тест проверяет 29 дней хранения, истечение срока, выход, смену идентификатора, параметры cookie и очистку старых файлов.

## Сеть и уведомления

При недоступной сети или сервере service worker показывает сохранённую страницу со спиннером. Она проверяет соединение каждые 5 секунд и автоматически открывает исходную страницу, сохраняя ссылку на событие. В работающем UI потеря сети также включает экран ожидания. POST-запросы после восстановления связи автоматически не повторяются.

Для офлайн-открытия нужен хотя бы один успешный визит после обновления: браузер должен установить service worker и сохранить `offline.html`. На самом первом посещении без интернета браузер ещё не имеет файлов сайта. Требуются HTTPS (либо localhost для теста) и поддержка service worker.

Кнопки уведомлений нет. При каждом открытии страницы UI запрашивает разрешение, если браузер ещё не сохранил решение. Если нужен жест пользователя, запрос повторяется при первом нажатии или клавише. При уже выданном разрешении восстанавливается push-подписка. После явного запрета браузер не позволяет программно запросить разрешение повторно: его можно изменить в настройках сайта. См. [Notification.requestPermission](https://developer.mozilla.org/en-US/docs/Web/API/Notification/requestPermission_static).

## Удаление истории

В списках звонков и СМС можно выбирать отдельные записи или всю текущую страницу. Кнопка показывает количество выбранных записей; перед удалением появляется подтверждение. Выбор ограничен видимыми записями, поиск и пагинация учитываются. После удаления последней страницы UI переходит на оставшуюся страницу.

`POST index.php?action=delete_events` принимает `kind` (`calls` или `sms`), `ids` (1–100 строк) и сессионный `csrf_token`. Нужны ключ доступа и авторизация администратора. Повторный запрос с уже удалёнными ID безопасен. Вместе со звонком удаляется его аудиофайл, если на него больше не ссылаются другие звонки. Ошибка удаления файла отображается в UI; осиротевшая запись недоступна через скачивание. Удаление необратимо.

JSON-хранилище обновляется атомарно под общей блокировкой `<store>.lock`. Повреждённый JSON не перезаписывается. Локальные файлы с историей и ключами не входят в репозиторий.

Проверки без production-конфигурации:

```sh
node --test tests/web_ui.test.cjs
php tests/web_event_store_test.php
```

PHP-тест проверяет удаление и сохранность аудио, валидацию, повреждённое хранилище и одновременное добавление/удаление тремя процессами. JS-тесты проверяют автоматическое разрешение/подписку, обработку запрета, офлайн-ответы service worker и отправку выбранных ID после подтверждения.

## Отправка СМС

Раздел «Отправить СМС» позволяет выбрать SIM, получателя и текст, затем отслеживать результат. Сначала загрузите `sms_outbox_store.php` и `sms_outbox.php`, обновите и перезапустите бот; затем замените `index.php`. Подробности и команды Telegram/email: [отправка СМС](../docs/sms-sending.md).

## Голосовые вызовы

Раздел «Голосовой вызов» записывает сообщение с микрофона или принимает аудиофайл. Можно позвонить сразу либо назначить время по Москве, посмотреть результат и отменить ожидающий вызов. Команды Telegram, установка и поведение при сбоях: [голосовые вызовы и расписание](../docs/voice-calls.md).

## Повторное распознавание сохранённых звонков

Административный инструмент `transcription_maintenance.php` и библиотека `transcription_maintenance_store.php` загружаются рядом с `common.php` и `event_store.php`. Все запросы требуют существующий API-заголовок `Authentication`; ответы не кэшируются. Через этот API можно читать историю и аудио, поэтому ключ должен оставаться секретным.

1. `GET transcription_maintenance.php` возвращает `calls`: для каждого звонка — `record`, версию всей записи `version` и SHA-256 аудио `audio_sha256` (либо `null`, если файла нет). Сохраните ответ как `snapshot.json` в закрытом рабочем каталоге.
2. `GET transcription_maintenance.php?audio_id=<id>` скачивает связанный WAV. Сохраните его как `audio/<audio_sha256>.wav`; можно использовать локальную копию с совпадающим хешем.
3. Запустите `python tools/retranscribe_snapshot.py snapshot.json audio results` в окружении бота с установленным GigaAM. Каталог `results` должен быть новым. По умолчанию используются два канала параллельно и два CPU-потока, без обращения к настройкам сайта. Параметр `--gigaam-model-path` позволяет указать локальную модель. Скрипт проверяет хеши, назначает «Я»/номер согласно направлению звонка, сохраняет результаты и `plan.json`. Ошибка ASR прерывает подготовку плана; отсутствие речи даёт пустую расшифровку. Звонки без аудио пропускаются и перечисляются в `summary.json`.
4. После проверки результатов отправьте содержимое `results/plan.json` как JSON в `POST transcription_maintenance.php`. План содержит массив `updates` (до 1000 записей), каждая с `id`, `version`, `audio_sha256`, `transcription`. Ответ перечисляет `updated_ids`, `unchanged_ids`, `conflicts` и имя резервной копии `backup`.
5. Повторным GET проверьте совпадение текстов и сохранность остальных полей. Конфликты требуют свежего снимка и проверки; старый план не должен применяться принудительно.

Обновление меняет только `transcription` у существующего ID. Оно не вызывает `save_call.php`, не создаёт дубликаты и не отправляет уведомления. Пустой успешный результат очищает старый текст. Общая блокировка с добавлением/удалением звонков сохраняет новые записи; проверка версии и хеша не позволяет перезаписать изменённый звонок или восстановить удалённый. Перед каждой фактической записью сохраняется полная копия актуального `calls.json` в закрытом каталоге данных: `calls-before-retranscription-<UTC>-<random>.json`, права `0600`. При ошибке резервного копирования история не меняется. Повтор идентичного плана не пишет данные заново.

Проверки: `php tests/web_transcription_maintenance_test.php` и `php tests/web_event_store_test.php`.

## Проверка качества распознавания

Кнопка «Проверить качество» в настройках открывает `transcription_test.php` с выбранным на форме движком. Можно записать голос (HTTPS и разрешение микрофона), выбрать или перетащить файл, прослушать его и распознать. Переключение движка на этой странице не меняет настройки звонков. Результат — текст, длительность аудио и время обработки, без автоматической оценки точности. Речь без распознанного текста отличается от тишины.

Установка: загрузить `transcription_test.php`, `transcription_test_store.php`, `transcription_test_worker.php`, `transcription_test.js`, `transcription_test.css`, обновить бот и перезапустить его, затем обновить `index.php`. Приватный `common.php` не меняется. Бот находит worker endpoint рядом с `CALL_TRANSCRIBE_SETTINGS_URL`, используя существующий API-ключ. Доступ к странице требует обычную сессию, загрузка — CSRF; API бота отдельно защищён заголовком `Authentication`.

Лимит — 5 минут и 20 МБ (либо меньший лимит PHP). WAV, MP3, M4A/AAC, OGG/Opus, WebM и FLAC декодируются в моно 16 кГц. Тест использует те же модели и параметры VAD, что звонки, с общей блокировкой распознавателя и одной моделью в памяти. Не создаются записи журнала звонков или уведомления. Очередь ограничена пятью активными заданиями; ожидание более часа завершается ошибкой. Исходник удаляется после результата/ошибки, текст хранится сутки в закрытом `DATA_STORAGE_DIR/transcription-tests`; фоновый worker очищает истёкшие данные. После обновления вкладки последний результат восстанавливается в пределах этого срока. При потере ответа загрузка повторяется с тем же ID, завершение обработки также идемпотентно.

Проверки: `php tests/transcription_test_store_test.php`, `python -m unittest discover -s tests -p 'test_transcription*.py'`, `node --test tests/transcription_quality_ui.test.cjs`.
