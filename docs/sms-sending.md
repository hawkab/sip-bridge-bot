# Отправка СМС

Сообщения из веб-интерфейса, Telegram и email попадают в общую очередь на PHP-хостинге. Бот забирает задания по исходящему HTTPS-соединению и отправляет их через существующий TCP API Yeastar TG. Открывать порты Asterisk-сервера для хостинга не нужно.

## Настройка

В `.env` бота задайте соответствие физических SIM-портов и номеров:

```dotenv
SMS_SIM_PORTS_JSON=[{"port":1,"number":"+79991111111"},{"port":2,"number":"+79992222222"}]
SMS_SPAN_OFFSET=1
```

Номера в примере условные. Не добавляйте реальные номера и ключи в репозиторий. У TG200 физический порт 1 соответствует span 2, порт 2 — span 3. Для другой модели проверьте соответствие; смещение задаёт `SMS_SPAN_OFFSET`.

`SMS_OUTBOX_URL` по умолчанию указывает на `sms_outbox.php` рядом с `EVENT_STORE_SMS_URL`. Используется существующий `EVENT_STORE_AUTH_TOKEN`. На хостинг сначала загрузите `sms_outbox_store.php` и `sms_outbox.php`, затем обновите бот и перезапустите его, после этого загрузите `index.php`. После первого подключения бота список отправителей автоматически появляется в UI.

## Использование

Веб: список **СМС** → **Новая СМС** → отправитель и номер получателя → чат. В карточке входящей СМС переписка открывается с фиксированным получателем. Известная SIM заблокирована; если определить её не удалось, выберите номер отправителя вручную. В чате отображаются входящие сообщения и статусы исходящих для этой пары номеров. Выход из аккаунта очищает черновик.

Telegram, только с настроенного аккаунта администратора:

```text
/sms_ports
/sms 1 +79992222222 Привет! Проверка связи.
/sms 2 +79991111111 Ответ со второй SIM.
/sms +79991111111 +79992222222 Можно указать номер отправителя.
```

Кавычки вокруг текста не нужны. Кавычки, апострофы, знак `+`, кириллица и переносы строк Telegram сохраняются.

Email: отправьте письмо в существующий IMAP-ящик бота с разрешённого адреса (`EMAIL_ALLOWED_SENDERS`). Укажите действующий `EMAIL_COMMAND_HASH`, затем команду **одной строкой** в теле письма:

```text
<ваш EMAIL_COMMAND_HASH>
/sms 2 +79991111111 Проверка отправки из email.
```

Ответ о постановке в очередь возвращается в исходный канал. Результат отправки отображается в UI; отдельные отбивки о результате в Telegram и email отключены. Во входящих SMS-уведомлениях строка «Кому» содержит телефонный номер принимающей SIM из `SMS_SIM_PORTS_JSON`. Если соответствие неизвестно, это указано явно вместе с портом SIM.

## Статусы и повторная отправка

- **В очереди** — задание сохранено; ждёт шлюз.
- **Отправляется** — бот забрал задание.
- **Отправлено** — получено событие TG `UpdateSMSSend` со статусом 1. Это подтверждение отправки оператору, не отчёт о доставке на телефон.
- **Ошибка** — шлюз отклонил отправку либо срок ожидания в очереди превысил 24 часа.
- **Нет подтверждения** — оборвалась связь, отсутствует статус шлюза либо бот перезапущен во время отправки. Сообщение автоматически не повторяется: сначала проверьте получателя.

Ограничение TG — 1024 байта UTF-8 до URL-кодирования. Длинные сообщения могут разбиваться на несколько СМС. Между командами отправки через один порт выдерживается минимум 10 секунд. [Документация Yeastar TG SMS API](https://support.yeastar.com/hc/en-us/articles/217392758-How-to-Use-TG-SMS-API).

Очередь находится в закрытом `DATA_STORAGE_DIR/sms-outbox.json`; изменения атомарны и защищены блокировкой. UI требует авторизацию и CSRF-токен. У каждого запроса есть ключ идемпотентности, у взятого задания — отдельный токен. Сетевые повторы сохраняют результат, но не повторяют физическую отправку. Старые взятые задания становятся `unknown`, а не возвращаются в очередь. Одновременно допускается не более 50 ожидающих заданий.

## Проверки

```sh
python -m unittest tests.test_sms_gateway tests.test_sms_commands -v
php tests/sms_outbox_test.php
node --test tests/web_ui.test.cjs
```

Проверяются TCP-протокол, единственная команда отправки, корреляция статусов, неизвестный результат без повтора, Unicode, обе схемы индексов multipart SMS, авторизация Telegram/email, сохранение текста, повтор записи результата, валидация PHP-очереди, идемпотентность и блокировка повторного получения заданий.
