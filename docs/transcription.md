# Распознавание записей звонков

По умолчанию используется **GigaAM v3 e2e RNN-T ONNX int8** для русской речи на CPU. **faster-whisper** остаётся доступен через UI или окружение. Оба движка обрабатывают левый и правый каналы отдельно и возвращают прежний формат `conversation` с `speaker`, `channel`, `start`, `end`, `start_hms`, `end_hms`, `text`. PDF, Telegram и PHP-хостинг используют этот формат без миграции данных.

GigaAM всегда использует Silero VAD: порог 0.5, минимальная длительность речи 0 мс, пауза 500 мс, поля по 300 мс, отрезки не длиннее 20 секунд. Отдельный вызов распознавателя для каждого интервала сохраняет повторные сообщения IVR. На пустом канале распознаватель не вызывается. Временные метки переводятся обратно на исходную шкалу времени. Токенные выравнивания приблизительны; при некорректных данных сохраняется весь текст и границы VAD-интервала.

Whisper также получает отдельные VAD-интервалы по умолчанию. Используются `temperature=0`, `condition_on_previous_text=False`, `word_timestamps=True`, стандартные пороги 2.4 / -1.0 / 0.6 и `hallucination_silence_threshold=2`. Эти пороги не гарантируют отсутствие галлюцинаций: проверка compression ratio сама по себе не является фильтром удаления текста. На тихой речи `small` всё ещё уступает более подходящему русскоязычному движку. Не следует удалять слова вроде «Спасибо» по чёрному списку или считать старые автоматические расшифровки эталоном.

## Установка и выбор движка

Обновите зависимости в окружении бота:

```sh
/opt/sms/venv/bin/pip install -r /opt/sms/requirements.txt
```

Модель ONNX загружается с Hugging Face при первом использовании. Для предварительной загрузки выполните команду от пользователя сервиса, чтобы использовать тот же кэш:

```sh
sudo -u asterisk /opt/sms/venv/bin/python -c 'import onnx_asr; onnx_asr.load_model("gigaam-v3-e2e-rnnt", quantization="int8", providers=["CPUExecutionProvider"])'
```

Проверить запись без отправки уведомлений и изменения веб-хостинга:

```sh
cd /opt/sms
venv/bin/python -m integrations.transcription recording.wav --backend gigaam -o /tmp/gigaam-test.json
venv/bin/python -m integrations.transcription recording.wav --backend whisper --model small -o /tmp/whisper-test.json
```

CLI использует указанный движок и не читает настройку UI. Сервис читает настройку перед каждым новым распознаванием. Для UI установите [обновление PHP-хостинга](../web/README.md) и перезапустите обновлённый бот в согласованное время. Обновление исходников само по себе не перезапускает сервис.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `CALL_TRANSCRIBE_BACKEND` | `gigaam` | Движок до первого успешного чтения UI |
| `CALL_TRANSCRIBE_SETTINGS_URL` | `transcription_settings.php` рядом с `EVENT_STORE_CALL_URL` | Пустое значение отключает чтение UI |
| `CALL_TRANSCRIBE_SETTINGS_TIMEOUT_SECONDS` | `3` | Таймаут запроса настроек |
| `CALL_TRANSCRIBE_CPU_THREADS` | `2` | Число потоков ASR, одинаковое для обоих движков |
| `CALL_TRANSCRIBE_GIGAAM_MODEL_PATH` | пусто | Локальный каталог совместимой ONNX-модели; иначе загрузка из кэша/Hugging Face |
| `CALL_TRANSCRIBE_MODEL` | `small` | Только модель faster-whisper |
| `CALL_TRANSCRIBE_DEVICE` | `cpu` | Только устройство faster-whisper |
| `CALL_TRANSCRIBE_COMPUTE_TYPE` | `int8` | Только вычисления faster-whisper |
| `CALL_TRANSCRIBE_VAD_FILTER` | `1` | VAD для Whisper; GigaAM всегда использует VAD |
| `CALL_TRANSCRIBE_VAD_MIN_SILENCE_MS` | `500` | Пауза для разделения речи |

Не указывайте `gigaam` в `CALL_TRANSCRIBE_MODEL`: это идентификатор модели Whisper. Для переключения используется отдельный `CALL_TRANSCRIBE_BACKEND` или выбор в UI. При недоступности хостинга сохраняется последний выбор в памяти процесса; после перезапуска до успешного запроса используется окружение. Ошибка загрузки модели не запускает другой движок скрытно.

Кэшируется одна загруженная модель. Переключение сериализовано с обработкой записей; параллельные звонки не могут сменить движок посреди распознавания. Настройка UI меняет только выбор движка, а параметры моделей остаются в окружении сервера.

## Проверка

```sh
python -m unittest discover -s tests -v
```

Тесты проверяют обход ASR на тишине, сохранение повторных реплик и исходных временных меток, целостность текста после сборки токенов, отклонение mono-записи, повторное использование модели, переключение между очередными записями и отказоустойчивое чтение настроек.

В исследовании 2026-09-20 сравнены 7 вариантов на 60 фрагментах из 48 записей, затем GigaAM обработала все 133 исходных стереозаписи. Проверка интеграции на всём архиве подтвердила сохранение текста при разбиении на реплики и допустимые временные границы. Приватные аудиофайлы и расшифровки не входят в репозиторий. Без независимого ручного эталона WER не заявляется.

На Raspberry Pi / Cortex-A76, CPU, 2 потока, шесть одинаковых монофрагментов длительностью 184.66 секунды: GigaAM + VAD — 6.09 секунды, Whisper small + встроенный VAD/пороги — 75.39 секунды (без загрузки модели). Пиковый RSS — около 537 и 1070 MiB. Это небольшой однократный замер, а не гарантия скорости для любых звонков; Whisper с отдельными VAD-интервалами имеет другой профиль затрат.

Источники: [GigaAM](https://github.com/salute-developers/GigaAM), [onnx-asr](https://github.com/istupakov/onnx-asr), [faster-whisper](https://github.com/SYSTRAN/faster-whisper).
