# Распознавание записей звонков

По умолчанию используется **GigaAM v3 e2e RNN-T ONNX int8** для русской речи на CPU. **faster-whisper** остаётся доступен через UI или окружение. Оба движка обрабатывают левый и правый каналы отдельно и возвращают прежний формат `conversation` с `speaker`, `channel`, `start`, `end`, `start_hms`, `end_hms`, `text`. PDF, Telegram и PHP-хостинг используют этот формат без миграции данных.

GigaAM всегда использует Silero VAD: порог 0.5, минимальная длительность речи 0 мс, пауза 500 мс, поля по 300 мс, отрезки не длиннее 20 секунд. Отдельный вызов распознавателя для каждого интервала сохраняет повторные сообщения IVR. На пустом канале распознаватель не вызывается. Временные метки переводятся обратно на исходную шкалу времени. Токенные выравнивания приблизительны; при некорректных данных сохраняется весь текст и границы VAD-интервала.

Whisper также получает отдельные VAD-интервалы по умолчанию. Используются `temperature=0`, `condition_on_previous_text=False`, `word_timestamps=True`, стандартные пороги 2.4 / -1.0 / 0.6 и `hallucination_silence_threshold=2`. Эти пороги не гарантируют отсутствие галлюцинаций: проверка compression ratio сама по себе не является фильтром удаления текста. На тихой речи `small` всё ещё уступает более подходящему русскоязычному движку. Не следует удалять слова вроде «Спасибо» по чёрному списку или считать старые автоматические расшифровки эталоном.

## Установка и выбор движка

Обновите зависимости в окружении бота:

```sh
/opt/sms/venv/bin/pip install -r /opt/sms/requirements.txt
```

Модель ONNX загружается с Hugging Face при первом использовании. Для предварительной загрузки выполните команду от пользователя сервиса, чтобы использовать тот же кэш:

```sh
sudo -u asterisk /opt/sms/venv/bin/python -c 'import onnx_asr; onnx_asr.load_model("gigaam-v3-e2e-rnnt", quantization="int8", providers=["CPUExecutionProvider"])'
```

Проверить запись без отправки уведомлений и изменения веб-хостинга:

```sh
cd /opt/sms
venv/bin/python -m integrations.transcription recording.wav --backend gigaam -o /tmp/gigaam-test.json
venv/bin/python -m integrations.transcription recording.wav --backend whisper --model small -o /tmp/whisper-test.json
```

CLI использует указанный движок и не читает настройку UI. Сервис читает настройку перед каждым новым распознаванием. Для UI установите [обновление PHP-хостинга](../web/README.md) и перезапустите обновлённый бот в согласованное время. Обновление исходников само по себе не перезапускает сервис.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `CALL_TRANSCRIBE_BACKEND` | `gigaam` | Движок до первого успешного чтения UI |
| `CALL_TRANSCRIBE_SETTINGS_URL` | `transcription_settings.php` рядом с `EVENT_STORE_CALL_URL` | Пустое значение отключает чтение UI |
| `CALL_TRANSCRIBE_SETTINGS_TIMEOUT_SECONDS` | `3` | Таймаут запроса настроек |
| `CALL_TRANSCRIBE_CPU_THREADS` | `2` | Вычислительные потоки ASR на worker/session, одинаковое значение для обоих движков |
| `CALL_TRANSCRIBE_CHANNEL_WORKERS` | `1` | `1`: каналы по очереди; `2`: одновременно, с сохранением их порядка |
| `CALL_TRANSCRIBE_GIGAAM_CHANNEL_WORKERS` | значение `CALL_TRANSCRIBE_CHANNEL_WORKERS` | Переопределение числа channel worker только для GigaAM |
| `CALL_TRANSCRIBE_GIGAAM_MODEL_PATH` | пусто | Локальный каталог совместимой ONNX-модели; иначе загрузка из кэша/Hugging Face |
| `CALL_TRANSCRIBE_MODEL` | `small` | Только модель faster-whisper |
| `CALL_TRANSCRIBE_DEVICE` | `cpu` | Только устройство faster-whisper |
| `CALL_TRANSCRIBE_COMPUTE_TYPE` | `int8` | Только вычисления faster-whisper |
| `CALL_TRANSCRIBE_VAD_FILTER` | `1` | VAD для Whisper; GigaAM всегда использует VAD |
| `CALL_TRANSCRIBE_VAD_MIN_SILENCE_MS` | `500` | Пауза для разделения речи |

Не указывайте `gigaam` в `CALL_TRANSCRIBE_MODEL`: это идентификатор модели Whisper. Для переключения используется отдельный `CALL_TRANSCRIBE_BACKEND` или выбор в UI. При недоступности хостинга сохраняется последний выбор в памяти процесса; после перезапуска до успешного запроса используется окружение. Ошибка загрузки модели не запускает другой движок скрытно.

Кэшируется одна загруженная модель. Переключение сериализовано с обработкой записей; параллельные звонки не могут сменить движок посреди распознавания. Настройка UI меняет только выбор движка, а параметры моделей остаются в окружении сервера.

## Параллельная обработка каналов

Для Raspberry Pi с четырьмя Cortex-A76 проверен режим:

```dotenv
CALL_TRANSCRIBE_BACKEND=gigaam
CALL_TRANSCRIBE_CHANNEL_WORKERS=1
CALL_TRANSCRIBE_GIGAAM_CHANNEL_WORKERS=2
CALL_TRANSCRIBE_CPU_THREADS=2
CALL_TRANSCRIBE_VAD_FILTER=1
```

Одна запись остаётся единицей очереди: следующие звонки не начинают распознаваться одновременно с текущим. Внутри записи работают максимум два channel worker. GigaAM использует общие ONNX sessions с независимым состоянием декодирования каждого вызова; При включении параллельности для Whisper он получает `num_workers=2`, чтобы CTranslate2 действительно выполнял оба запроса параллельно. Даже при ошибке одного канала второй завершается до удаления временных WAV и освобождения записи для смены движка.

Параллельность не улучшает качество распознавания. В замере 2026-09-20 результаты GigaAM, включая текст, говорящих и временные метки, полностью совпали во всех режимах. Шесть стереофрагментов из пользовательских записей, 283.26 с суммарно: короткий звонок, повторяющийся IVR, канал с цифровой тишиной, начало длинного разговора и два отрывка с речью обоих участников. Каждая комбинация запускалась в отдельном процессе с `nice=15`, после прогрева, три повтора. Время включает чтение WAV, VAD, ASR и сборку JSON; загрузка модели исключена.

| GigaAM: workers × threads | Медиана времени всего набора | CPU-секунды | Пиковый RSS |
| --- | --- | --- | --- |
| 1 × 2 | 22.39 с | 52.23 | 530 MiB |
| 2 × 1 | 21.81 с | 43.97 | 681 MiB |
| 2 × 2 | 17.68 с | 52.16 | 686 MiB |
| 1 × 4 | 21.13 с | 75.12 | 513 MiB |

Режим 2 × 2 сократил ожидание на 21% относительно 1 × 2 при близких суммарных CPU-затратах, но более высокой мгновенной загрузке. Режим 2 × 1 экономит CPU, однако сокращает ожидание всего на 3%. Если речь есть только в одном канале, ускорения от второго worker может не быть. Общий default оставлен последовательным для предсказуемой нагрузки на других серверах; рекомендуемая конфигурация этого Raspberry Pi указана выше. Это небольшой набор без активных звонков во время теста, а не нагрузочный тест телефонии.

Whisper small int8 с отдельными VAD-интервалами проверен на тех же шести стереофрагментах, по одному полному проходу после прогрева:

| Whisper: workers × threads | Время набора | CPU-секунды | Пиковый RSS |
| --- | --- | --- | --- |
| 1 × 2 | 390.02 с | 817.52 | 1021 MiB |
| 2 × 2 | 382.10 с | 1250.29 | 1523 MiB |

Результаты Whisper также полностью совпали. Разница времени около 2% в однократном замере не подтверждает полезного ускорения; CPU-затраты выросли на 53%, RSS — примерно на 49%. Поэтому для этого сервера сохраняется общий `CALL_TRANSCRIBE_CHANNEL_WORKERS=1` и задаётся только `CALL_TRANSCRIBE_GIGAAM_CHANNEL_WORKERS=2`. При выборе Whisper в UI каналы снова обрабатываются по очереди, при выборе GigaAM — одновременно. В CLI явный `--channel-workers` применяется к выбранному движку.

Повторить замер на своём наборе без отправки уведомлений, изменения расшифровок или обращения к настройкам UI:

```sh
python tools/benchmark_transcription.py /path/to/stereo-wavs \
  --backend gigaam --channel-workers 2 --cpu-threads 2 --repeats 3 > result.jsonl
```

Для каждой комбинации запускайте новый процесс. Утилита сохраняет время, CPU, RSS и SHA-256 результата без распознанного текста. Имена исходных файлов в JSONL могут содержать личные данные. Для Whisper укажите `--backend whisper --model small`.

## Проверка

```sh
python -m unittest discover -s tests -v
```

16 тестов проверяют порядок и перекрытие параллельных каналов, ожидание второго канала при ошибке, однократную загрузку общей модели, обход ASR на тишине, сохранение повторных реплик и исходных временных меток, целостность текста после сборки токенов, отклонение mono-записи, повторное использование модели, переключение между очередными записями и отказоустойчивое чтение настроек.

В исследовании 2026-09-20 сравнены 7 вариантов на 60 фрагментах из 48 записей, затем GigaAM обработала все 133 исходных стереозаписи. Проверка интеграции на всём архиве подтвердила сохранение текста при разбиении на реплики и допустимые временные границы. Повторный прогон всех 133 записей с двумя channel worker дал полностью совпадающий `conversation`, включая текст, каналы и временные метки. Приватные аудиофайлы и расшифровки не входят в репозиторий. Без независимого ручного эталона WER не заявляется.

На Raspberry Pi / Cortex-A76, CPU, 2 потока, шесть одинаковых монофрагментов длительностью 184.66 секунды: GigaAM + VAD — 6.09 секунды, Whisper small + встроенный VAD/пороги — 75.39 секунды (без загрузки модели). Пиковый RSS — около 537 и 1070 MiB. Это небольшой однократный замер, а не гарантия скорости для любых звонков; Whisper с отдельными VAD-интервалами имеет другой профиль затрат.

Источники: [GigaAM](https://github.com/salute-developers/GigaAM), [onnx-asr](https://github.com/istupakov/onnx-asr), [faster-whisper](https://github.com/SYSTRAN/faster-whisper).
