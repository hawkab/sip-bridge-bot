# Распознавание записей звонков

По умолчанию используется **GigaAM v3 e2e RNN-T ONNX int8** для русской речи на CPU. **faster-whisper**, **T-one** и **NVIDIA Nemotron 3.5 ASR** доступны через UI или окружение. Все движки обрабатывают левый и правый каналы отдельно и возвращают прежний формат `conversation` с `speaker`, `channel`, `start`, `end`, `start_hms`, `end_hms`, `text`. PDF, Telegram и PHP-хостинг используют этот формат без миграции данных.

GigaAM, T-one и Nemotron всегда используют Silero VAD: порог 0.5, минимальная длительность речи 0 мс, пауза 500 мс, поля по 300 мс, отрезки не длиннее 20 секунд. Отдельный вызов распознавателя для каждого интервала сохраняет повторные сообщения IVR. На пустом канале распознаватель не вызывается. Временные метки переводятся обратно на исходную шкалу времени. Токенные выравнивания приблизительны; при некорректных данных сохраняется весь текст и границы VAD-интервала.

Whisper также получает отдельные VAD-интервалы по умолчанию. Используются `temperature=0`, `condition_on_previous_text=False`, `word_timestamps=True`, стандартные пороги 2.4 / -1.0 / 0.6 и `hallucination_silence_threshold=2`. Эти пороги не гарантируют отсутствие галлюцинаций: проверка compression ratio сама по себе не является фильтром удаления текста. На тихой речи `small` всё ещё уступает более подходящему русскоязычному движку. Не следует удалять слова вроде «Спасибо» по чёрному списку или считать старые автоматические расшифровки эталоном.

## Установка и выбор движка

Обновите зависимости в окружении бота:

```sh
/opt/sms/venv/bin/pip install -r /opt/sms/requirements.txt
```

Модель GigaAM ONNX загружается с Hugging Face при первом использовании. Для предварительной загрузки выполните команду от пользователя сервиса, чтобы использовать тот же кэш:

```sh
sudo -u asterisk /opt/sms/venv/bin/python -c 'import onnx_asr; onnx_asr.load_model("gigaam-v3-e2e-rnnt", quantization="int8", providers=["CPUExecutionProvider"])'
```

Проверить запись без отправки уведомлений и изменения веб-хостинга:

```sh
cd /opt/sms
venv/bin/python -m integrations.transcription recording.wav --backend gigaam -o /tmp/gigaam-test.json
venv/bin/python -m integrations.transcription recording.wav --backend whisper --model small -o /tmp/whisper-test.json
```

CLI использует указанный движок и не читает настройку UI. Сервис читает настройку перед каждым новым распознаванием. Для UI установите [обновление PHP-хостинга](../web/README.md) и перезапустите обновлённый бот в согласованное время. Обновление исходников само по себе не перезапускает сервис.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `CALL_TRANSCRIBE_BACKEND` | `gigaam` | Движок до первого успешного чтения UI |
| `CALL_TRANSCRIBE_SETTINGS_URL` | `transcription_settings.php` рядом с `EVENT_STORE_CALL_URL` | Пустое значение отключает чтение UI |
| `CALL_TRANSCRIBE_SETTINGS_TIMEOUT_SECONDS` | `3` | Таймаут запроса настроек |
| `CALL_TRANSCRIBE_CPU_THREADS` | `2` | Вычислительные потоки ASR на worker/session, Whisper и ONNX-модели; не управляет внутренним пулом Nemotron |
| `CALL_TRANSCRIBE_CHANNEL_WORKERS` | `1` | `1`: каналы по очереди; `2`: одновременно, с сохранением их порядка |
| `CALL_TRANSCRIBE_GIGAAM_CHANNEL_WORKERS` | значение `CALL_TRANSCRIBE_CHANNEL_WORKERS` | Переопределение числа channel worker только для GigaAM |
| `CALL_TRANSCRIBE_TONE_CHANNEL_WORKERS` | значение `CALL_TRANSCRIBE_GIGAAM_CHANNEL_WORKERS` | Число параллельных каналов T-one |
| `CALL_TRANSCRIBE_TONE_MODEL_PATH` | `/opt/sms/var/models/tone` | Проверенная локальная модель T-one |
| `CALL_TRANSCRIBE_NEMOTRON_MODEL_PATH` | `/opt/sms/var/models/nemotron/nemotron-3.5-asr-streaming-0.6b.q8_0.gguf` | Локальная модель NVIDIA |
| `CALL_TRANSCRIBE_NEMOTRON_LIBRARY_PATH` | `/opt/sms/var/models/nemotron/runtime/lib/libnemo_speech_asr_c.so.1` | C ABI NeMo-Speech.cpp 0.1.0 |
| `CALL_TRANSCRIBE_GIGAAM_MODEL_PATH` | пусто | Локальный каталог совместимой ONNX-модели; иначе загрузка из кэша/Hugging Face |
| `CALL_TRANSCRIBE_MODEL` | `small` | Только модель faster-whisper |
| `CALL_TRANSCRIBE_DEVICE` | `cpu` | Только устройство faster-whisper |
| `CALL_TRANSCRIBE_COMPUTE_TYPE` | `int8` | Только вычисления faster-whisper |
| `CALL_TRANSCRIBE_VAD_FILTER` | `1` | VAD для Whisper; остальные движки всегда используют VAD |
| `CALL_TRANSCRIBE_VAD_MIN_SILENCE_MS` | `500` | Пауза для разделения речи |

Не указывайте `gigaam` в `CALL_TRANSCRIBE_MODEL`: это идентификатор модели Whisper. Для переключения используется отдельный `CALL_TRANSCRIBE_BACKEND` или выбор в UI. При недоступности хостинга сохраняется последний выбор в памяти процесса; после перезапуска до успешного запроса используется окружение. Ошибка загрузки модели не запускает другой движок скрытно.

Кэшируется одна загруженная модель. Переключение сериализовано с обработкой записей; параллельные звонки не могут сменить движок посреди распознавания. Настройка UI меняет только выбор движка, а параметры моделей остаются в окружении сервера.

## T-one и NVIDIA Nemotron 3.5 ASR

Установите модели заранее от пользователя сервиса. Установщики скачивают только веса и, для Nemotron, официальный CPU runtime; сверяют SHA-256 и фиксированные ревизии. Они не меняют зависимости рабочего Python-окружения и не переключают выбранный движок.

```sh
sudo -u asterisk /opt/sms/venv/bin/python /opt/sms/tools/install_tone.py
sudo -u asterisk /opt/sms/venv/bin/python /opt/sms/tools/install_nemotron.py
```

Для отдельной установки используйте `--root`. T-one принимает `--source` с уже скачанными `model.onnx` и `config.json`; Nemotron — `--archive` и `--model-file`. Контрольные суммы проверяются и для локальных файлов. Повторная установка поверх существующего runtime отклоняется, чтобы не менять файлы загруженной модели.

```sh
venv/bin/python -m integrations.transcription recording.wav --backend tone -o /tmp/tone.json
venv/bin/python -m integrations.transcription recording.wav --backend nemotron -o /tmp/nemotron.json
```

- **T-one**: русская телефонная речь, вход модели 8 кГц, 71 млн параметров, официальный ONNX FP16, greedy CTC. `onnx-asr` выполняет нужное преобразование частоты. Большая языковая модель KenLM не устанавливается; опубликованные авторами показатели с другим декодером нельзя приписывать этой конфигурации. Регистр и пунктуация моделью не восстанавливаются.
- **Nemotron 3.5 ASR**: распознавание текста с явным языком `ru-RU`, Q8 GGUF, NeMo-Speech.cpp 0.1.0 через C ABI. Это отдельная ASR-модель; **Nemotron-3-Diarization** размечает говорящих и сама слова не распознаёт. Каналы звонка уже разделены записью, дополнительная диаризация не требуется. Каналы Nemotron обрабатываются последовательно: runtime управляет собственным вычислительным пулом, и `CALL_TRANSCRIBE_CPU_THREADS` к нему не применяется. В JSON замеров число потоков для него обозначено `null`, а не выдано за два потока. Языковые служебные теги исключаются из текста и словесного выравнивания.

Новые модели не скачиваются при входящем звонке. Если установка отсутствует, проверка показывает явную ошибку. При переключении или остановке бота native handle освобождается только после завершения распознавания. В памяти остаётся одна выбранная модель; существующие записи и транскрибации не переписываются при выборе движка.

Оба новых движка доступны также на странице «Проверить качество», с тем же декодированием файлов/микрофона, проверкой тишины и построчными временными метками. Выбор в тесте не меняет сохранённую настройку звонков.

Источники и лицензии: [T-one, Apache 2.0](https://github.com/voicekit-team/T-one), [Nemotron 3.5 ASR, OpenMDW 1.1](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b), [NeMo-Speech.cpp, Apache 2.0](https://github.com/NVIDIA/NeMo-Speech.cpp), [назначение Nemotron-3-Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization).

## Сравнение на Raspberry Pi 5, 2026-10-02

Пилот до полного прогона архива: стереозапись 1374.50 с и запись 9.04 с, где старый Whisper писал реплики на тихом левом канале. Это исходные файлы без изменения аудио. Движки запускались по очереди, с `nice=10`, после прогрева на 8 с речи. Время включает чтение, VAD, ASR и сборку результата; загрузка модели исключена. RSS процесса измерялся каждые 0.5 с. CPU 100% означает все четыре ядра. GigaAM и T-one: два канала параллельно, по два вычислительных потока; Whisper: один канал, два потока; Nemotron: один канал, внутренний пул runtime. Это сравнение рабочих конфигураций, а не одинакового числа потоков.

| Движок | Длинная запись | Короткая запись | Пик RSS, длинная | CPU / 4 ядра | CPU-секунды, длинная |
| --- | --- | --- | --- | --- | --- |
| GigaAM v3 int8 | 107.90 с | 0.50 с | 1300 МиБ | 80.5% | 347.2 |
| T-one FP16, greedy | 235.81 с | 1.15 с | 1496 МиБ | 71.9% | 677.9 |
| Nemotron 3.5 Q8 | 886.56 с | 2.21 с | 1550 МиБ | 94.0% | 3332.3 |
| faster-whisper small int8 | 3145.36 с | 17.10 с | 1220 МиБ | 53.3% | 6705.0 |

Тихий канал остался без текста у всех четырёх вариантов: это заслуга общего VAD, а не доказательство превосходства новой акустической модели. Временные метки всех результатов находятся внутри файлов; длинные записи обработаны до конца. На длинной записи Whisper снова выдаёт посторонние реплики и многократные повторы; Nemotron искажает часть фраз шумного канала. T-one даёт отдельные более правдоподобные фразы, но не показывает общего преимущества над GigaAM, теряет пунктуацию и требует больше времени/RAM в этой конфигурации. Независимого ручного эталона нет: старые автоматические тексты не используются как правильные ответы, WER не заявляется.

Веса на диске: GigaAM — 215.9 МиБ, Whisper — 463.7 МиБ, T-one — 137.5 МиБ; Nemotron — 707.2 МиБ плюс CPU runtime 19.2 МиБ. Общее Python-окружение сюда не включено. Максимальная наблюдавшаяся температура в пилоте — 72.7 °C, троттлинг отсутствовал; прогоны шли без активных звонков. Температура зависит от предшествующей нагрузки, поэтому не служит прямой оценкой энергопотребления моделей.

Предварительная рекомендация — сохранить GigaAM основным и использовать новые варианты для проверки отдельных сложных записей. Parakeet TDT v3 был отсеян на компьютере до замеров Raspberry: часть коротких русских реплик становилась текстом на других языках, в том числе после укрупнения речевых интервалов. Это наблюдение на пользовательских записях, не общее утверждение о качестве модели.

Обновление 17.10.2026: [Parakeet повторно проверен на Raspberry](parakeet-20261017.md) через transcribe.cpp Q8 из статьи на Хабре и через ONNX int8, включая отдельный режим объединения соседних реплик до 20 секунд. Рекомендация сохранить GigaAM основным остаётся в силе; в новом отчёте приведены свежие замеры и ограничения оценки качества.

### Полный архив: GigaAM и T-one

После пилота Whisper и Nemotron исключены из дальнейшего сравнения по решению пользователя. Проверены **133 оригинальные стереозаписи, 8112.54 с (2 ч. 15 мин. 12.54 с)** на каждом из двух оставшихся движков. SHA-256 всех входных файлов сверены; исходники не изменялись. Два результата пилота каждого движка включены в итог без повторного распознавания, остальные 131 файл обработаны в одном новом процессе на движок. Условия те же: CPU Raspberry Pi 5, после прогрева, `nice=10`, два канала и два вычислительных потока. Один проход; время ожидания очереди и холодной загрузки модели не измерялось.

| Движок | Весь архив | Быстрее длительности аудио | Пиковый RSS | CPU / 4 ядра | CPU-секунды |
| --- | --- | --- | --- | --- | --- |
| GigaAM v3 int8 | 9 мин. 34 сек. | 14.14× | 1399 МиБ | 77.8% | 1784.9 |
| T-one FP16, greedy | 20 мин. 35 сек. | 6.57× | 1531 МиБ | 69.1% | 3414.5 |

GigaAM быстрее в **2.15 раза**, использует в **1.91 раза меньше CPU-времени**; пик RSS T-one выше примерно на 9.5%. Более низкая средняя загрузка CPU у T-one не означает меньшей вычислительной работы: она длится дольше. Максимум температуры полного сравнения — 68.85 °C, троттлинга не было. Все 266 результатов получены без ошибок выполнения; временные границы допустимы. Для каждого файла длительности речи по VAD полностью совпадают между движками. Все 28 каналов, помеченных VAD как не содержащие речь, остались без текста у обоих.

В двух коротких VAD-фрагментах (0.632 и 2.448 с) оба движка не дали текста. Ещё в двух (0.696 и 0.760 с) T-one оставил текст пустым, а GigaAM дал отдельные слова; эти пограничные случаи отмечены для прослушивания и не объявлены автоматически ни ошибками, ни улучшениями. Два срабатывания эвристики повторов у GigaAM связаны с повторяющимися заполнителями пауз внутри связных предложений; длинных бессмысленных циклов вроде наблюдавшихся у Whisper не обнаружено. Числа словами/цифрами, регистр, транслитерация и пунктуация не считаются сами по себе ошибками ASR.

По текстам качество смешанное: T-one иногда сохраняет больше слов в коротких сообщениях и лучше восстанавливает отдельные названия, но в других местах искажает слова и обрезает части повторных IVR-фраз. Общего преимущества над GigaAM не установлено. Это структурная проверка всего архива и разбор расхождений, а не ручная эталонная разметка всех записей; процент WER не заявляется. Вывод относится к испытанному **T-one с greedy-декодером без KenLM**, а не ко всем возможным конфигурациям T-one.

**Итог: сохранить GigaAM основным**, T-one оставить доступной альтернативой для проверки сложных фрагментов. Приватный отчёт содержит все 133 записи, обе расшифровки с временными метками и прослушиванием, CSV с 266 замерами и отдельный пилот четырёх движков. Аудио, номера и полные тексты в Git не включены; существующая история сайта не переписывалась.

## Параллельная обработка каналов

Для Raspberry Pi с четырьмя Cortex-A76 проверен режим:

```dotenv
CALL_TRANSCRIBE_BACKEND=gigaam
CALL_TRANSCRIBE_CHANNEL_WORKERS=1
CALL_TRANSCRIBE_GIGAAM_CHANNEL_WORKERS=2
CALL_TRANSCRIBE_CPU_THREADS=2
CALL_TRANSCRIBE_VAD_FILTER=1
```

Одна запись остаётся единицей очереди: следующие звонки не начинают распознаваться одновременно с текущим. Внутри записи работают максимум два channel worker. GigaAM использует общие ONNX sessions с независимым состоянием декодирования каждого вызова; При включении параллельности для Whisper он получает `num_workers=2`, чтобы CTranslate2 действительно выполнял оба запроса параллельно. Даже при ошибке одного канала второй завершается до удаления временных WAV и освобождения записи для смены движка.

Параллельность не улучшает качество распознавания. В замере 2026-09-20 результаты GigaAM, включая текст, говорящих и временные метки, полностью совпали во всех режимах. Шесть стереофрагментов из пользовательских записей, 283.26 с суммарно: короткий звонок, повторяющийся IVR, канал с цифровой тишиной, начало длинного разговора и два отрывка с речью обоих участников. Каждая комбинация запускалась в отдельном процессе с `nice=15`, после прогрева, три повтора. Время включает чтение WAV, VAD, ASR и сборку JSON; загрузка модели исключена.

| GigaAM: workers × threads | Медиана времени всего набора | CPU-секунды | Пиковый RSS |
| --- | --- | --- | --- |
| 1 × 2 | 22.39 с | 52.23 | 530 MiB |
| 2 × 1 | 21.81 с | 43.97 | 681 MiB |
| 2 × 2 | 17.68 с | 52.16 | 686 MiB |
| 1 × 4 | 21.13 с | 75.12 | 513 MiB |

Режим 2 × 2 сократил ожидание на 21% относительно 1 × 2 при близких суммарных CPU-затратах, но более высокой мгновенной загрузке. Режим 2 × 1 экономит CPU, однако сокращает ожидание всего на 3%. Если речь есть только в одном канале, ускорения от второго worker может не быть. Общий default оставлен последовательным для предсказуемой нагрузки на других серверах; рекомендуемая конфигурация этого Raspberry Pi указана выше. Это небольшой набор без активных звонков во время теста, а не нагрузочный тест телефонии.

Whisper small int8 с отдельными VAD-интервалами проверен на тех же шести стереофрагментах, по одному полному проходу после прогрева:

| Whisper: workers × threads | Время набора | CPU-секунды | Пиковый RSS |
| --- | --- | --- | --- |
| 1 × 2 | 390.02 с | 817.52 | 1021 MiB |
| 2 × 2 | 382.10 с | 1250.29 | 1523 MiB |

Результаты Whisper также полностью совпали. Разница времени около 2% в однократном замере не подтверждает полезного ускорения; CPU-затраты выросли на 53%, RSS — примерно на 49%. Поэтому для этого сервера сохраняется общий `CALL_TRANSCRIBE_CHANNEL_WORKERS=1` и задаётся только `CALL_TRANSCRIBE_GIGAAM_CHANNEL_WORKERS=2`. При выборе Whisper в UI каналы снова обрабатываются по очереди, при выборе GigaAM — одновременно. В CLI явный `--channel-workers` применяется к выбранному движку, кроме Nemotron: его native recognizer всегда обрабатывает каналы последовательно.

Повторить замер на своём наборе без отправки уведомлений, изменения расшифровок или обращения к настройкам UI:

```sh
python tools/benchmark_transcription.py /path/to/stereo-wavs \
  --backend gigaam --channel-workers 2 --cpu-threads 2 --repeats 3 > result.jsonl
```

Для каждой комбинации запускайте новый процесс. Утилита сохраняет время, CPU, RSS и SHA-256 результата без распознанного текста. Имена исходных файлов в JSONL могут содержать личные данные. Для Whisper укажите `--backend whisper --model small`.

## Проверка

```sh
python -m unittest discover -s tests -v
```

Тесты проверяют порядок и перекрытие параллельных каналов, ожидание второго канала при ошибке, однократную загрузку общей модели, обход ASR на тишине, сохранение повторных реплик и исходных временных меток, целостность текста после сборки токенов, отклонение mono-записи, повторное использование модели, переключение между очередными записями и отказоустойчивое чтение настроек.

В исследовании 2026-09-20 сравнены 7 вариантов на 60 фрагментах из 48 записей, затем GigaAM обработала все 133 исходных стереозаписи. Проверка интеграции на всём архиве подтвердила сохранение текста при разбиении на реплики и допустимые временные границы. Повторный прогон всех 133 записей с двумя channel worker дал полностью совпадающий `conversation`, включая текст, каналы и временные метки. Приватные аудиофайлы и расшифровки не входят в репозиторий. Без независимого ручного эталона WER не заявляется.

На Raspberry Pi / Cortex-A76, CPU, 2 потока, шесть одинаковых монофрагментов длительностью 184.66 секунды: GigaAM + VAD — 6.09 секунды, Whisper small + встроенный VAD/пороги — 75.39 секунды (без загрузки модели). Пиковый RSS — около 537 и 1070 MiB. Это небольшой однократный замер, а не гарантия скорости для любых звонков; Whisper с отдельными VAD-интервалами имеет другой профиль затрат.
